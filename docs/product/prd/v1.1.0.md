# PRD: REST-Api-with-Slim-PHP

Developer-focused API skeleton documentation covering purpose, use cases, endpoints, authentication, and technical requirements.

---

## 1. Purpose & Overview

The **REST-Api-with-Slim-PHP** (Version 1.1.0) is a modern, scalable RESTful API skeleton designed to accelerate backend development. Built on the lightweight Slim PHP 4 framework, it solves the "blank canvas" problem for PHP developers by providing a fully configured, production-ready project structure out of the box. 

This API skeleton delivers immediate business value by drastically reducing initial setup time. It comes pre-packaged with essential core features—including database integration, JWT authentication, email handling, and standardized logging—allowing developers to focus on building domain-specific business logic rather than wiring boilerplate code. 

---

## 2. Target Developer Use Cases

**Persona 1: The Rapid-Prototyping Startup Developer**
* **Goal:** Spin up a secure, functional backend for a new web or mobile application in hours, not days.
* **Pain Point:** Configuring routing, middleware, and database connections from scratch is time-consuming and error-prone.
* **Use Case:** Clones the repository, configures the `.env` file for their local MySQL instance, and immediately begins building custom CRUD endpoints on top of the existing architecture.

**Persona 2: The Enterprise Integration Engineer**
* **Goal:** Build a lightweight, standalone microservice that securely exposes specific database records (like a user directory) to an internal dashboard.
* **Pain Point:** Heavyweight frameworks carry too much overhead for simple microservices.
* **Use Case:** Utilizes the lightweight Slim 4 routing, standard REST principles, and built-in CORS support to seamlessly integrate this API with a decoupled frontend application.

---

## 3. Authentication & Authorization

This API ensures secure data access through a built-in token-based mechanism. 

* **Authentication Method:** JSON Web Tokens (JWT).
* **Capabilities:** Built-in support for both token generation and verification middleware.
* **Security Controls:** Handled via the `src/Common/auth.php` utility, allowing developers to secure specific routes or route groups easily.
* **CORS:** Cross-Origin Resource Sharing is enabled by default (via `src/App/Cors.php`) to safely accept requests from authorized frontend clients.

---

## 4. Endpoint Specifications

**Base Path:** `/`

The API currently includes foundational endpoints for system status checks and user management operations. Flexible custom responses and JSON encoding are supported natively.

| Endpoint | HTTP Method | Description |
| :--- | :--- | :--- |
| `/` | GET | Returns API help/welcome information |
| `/status` | GET | Retrieves current API health status |
| `/users` | GET | Fetches the complete list of users |
| `/users` | POST | Creates a new user record |
| `/users/{id}` | GET | Fetches details for a specific user ID |
| `/users/{id}` | PUT | Updates information for a specific user ID |
| `/users/{id}` | DELETE | Deletes a specific user |

> **Example: Create User Request**
> ```bash
> curl -X POST http://localhost:8080/users \
>   -H "Content-Type: application/json" \
>   -d '{"name": "Zhang San", "email": "zhangsan@example.com"}'
> ```

## 5. Technical Requirements

To ensure high performance and maintainability, the API relies on the following technical stack and system requirements:

* **Language Environment:** PHP 8.0 or higher.
* **Package Management:** Composer (for dependency resolution mapped in `composer.json`).
* **Web Server:** Apache or Nginx (Apache rewrite rules included via `public/.htaccess`).
* **Database:** MySQL (tested with the provided `northwind.sql` sample database).
* **Configuration:** Environment-based configuration using `.env` files (e.g., `DB_HOST`, `DB_NAME`, `DB_USER`).
* **Architecture:** Separation of concerns via a well-defined directory structure (`public/` for web entry, `src/` for core App/Controllers/Common utilities).

---

## 6. Testing & Documentation

Quality assurance and maintainability are built directly into the project lifecycle.

* **Testing Framework:** Complete integration testing powered by PHPUnit.
* **Configuration:** Managed via the included `phpunit.xml` configuration file.
* **Execution:** Tests can be run locally via the command line using `./vendor/bin/phpunit`.
* **Logging:** Database log handler included natively to ensure application errors and states are tracked effectively.
