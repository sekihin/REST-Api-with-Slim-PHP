# PRD: Intent-Driven, Context-Aware AI Assistant for UIS Knowledge Retrieval

**Labels:** enhancement, feature

# Problem Statement

Internal staff face significant inefficiencies when searching for knowledge within the UIS (USAC Information Share) system:

1. Time-Consuming Manual Search: Employees spend excessive time searching through dense documentation (Operation Manuals, troubleshooting FAQs, system email templates) to find answers.

2. High Workload on Front-Line Staff: Support staff are burdened with repetitive operational inquiries that could be automated.

3. "Blind Search Engine" Limitation: The current RAG system functions as a basic keyword search without understanding user intent or context.

The goal is to transform this from a "blind search engine" into an Intent-Driven, Context-Aware AI Assistant that understands what the user is looking for and provides precise, actionable responses.

# Solution

Build a Routed Hybrid RAG Architecture that:

1. Classifies User Intent: Uses the Doubao LLM (doubao-seed-2-0-mini-260215) to classify queries into 4 categories: faq, email_template, operation_manual, or general.

2. Routes to Specialized Retrieval Pipelines: Each intent routes to a dedicated retrieval pipeline optimized for that content type.

3. Performs Actions: Executes specific actions (e.g., finding software installers, retrieving shipping dates) and returns structured data.

4. Synthesizes Responses: Generates natural language answers using the LLM with context from retrieved documents.

# User Stories

1. As an internal staff member, I want to ask natural language questions about the UIS system, so that I can get instant answers without manually searching through documentation.

2. As an internal staff member, I want the system to automatically route my question to the appropriate knowledge base (FAQ, email templates, or operation manuals), so that I receive relevant results faster.

3. As an internal staff member, I want to query about software installers and receive structured data (download links, version info), so that I can quickly provide this to customers.

4. As an internal staff member, I want to query about buyout software shipping dates and receive structured data, so that I can accurately respond to customer inquiries.

5. As an internal staff member, I want the system to handle queries that don't match specific intents by falling back to a general search, so that I still receive useful results.

6. As an administrator, I want to index UIS documents (Operation Manuals, FAQs, Email Templates, Workflows) into Elasticsearch, so that they are searchable by the RAG system.

7. As an administrator, I want documents to be chunked using semantic chunking, so that retrieval is optimized for meaning rather than arbitrary length.

8. As an internal staff member, I want responses within acceptable SLA targets, so that the system is practical for daily use.

9. As an internal staff member, I want the system to gracefully handle queries that don't clearly match any intent, so that I'm not left without a response.

10. As a QA engineer, I want to test each domain service (KnowledgeBaseService, InventoryService, Order) in isolation, so that I can verify correctness before integration.

11. As a QA engineer, I want to run the existing CLI test to verify KnowledgeBaseService search functionality, so that I can validate the system works as expected.

# Implementation Decisions

## Architecture

User Query → Preprocessor → Intent Router (LLM) → Hybrid Retriever (ES 9.3.0, dense vectors) → Response Synthesizer → Action Executor

## Modules & Interfaces

|Module|Responsibility|Interface|
|---|---|---|
|QueryPreprocessor|Clean and normalize user input|preprocess(query: string): string|
|IntentRouter|Classify query into intent categories via LLM|route(query: string): IntentType|
|HybridRetriever|Retrieve documents from Elasticsearch using dense vectors|retrieve(query: string, intent: IntentType, k: number): Document[]|
|ResponseSynthesizer|Generate natural language answer using LLM|synthesize(query: string, context: Document[]): string|
|ActionExecutor|Execute specific actions and return structured data|execute(action: string, params: object): object|
|DocumentIndexer|Index documents into Elasticsearch|index(documents: Document[]): void|
## Tech Stack

- Language: PHP

- Search: Elasticsearch 9.3.0 (dense vectors)

- LLM: Doubao-seed-2-0-mini-260215 (256k token limit)

- Chunking: Semantic chunking prioritized

## Domain Services (Existing)

- App\Domain\Knowledge\KnowledgeBaseService

- App\Domain\Inventory\InventoryService

- App\Domain\Order\

## Data Sources

|Source Type|Storage|Content|
|---|---|---|
|Operation Manuals|Elasticsearch|UIS system documentation|
|FAQs|Elasticsearch|Troubleshooting guides, error codes|
|Email Templates|Elasticsearch|License expiration warnings, delivery notifications|
|Workflows|Elasticsearch|Operational procedures|

|Metric|Target|
|---|---|

|Intent Classification Accuracy|> 90%|

# Testing Decisions

## Unit Testing Strategy

- Test external behavior only, not implementation details

- Mock external dependencies (Elasticsearch, LLM API)

## Modules to Test in Isolation

1. QueryPreprocessor - Input normalization, edge cases

2. IntentRouter - Classification accuracy, fallback behavior

3. HybridRetriever - Retrieval with different intents, ranking

4. ActionExecutor - find_installer, get_shipping_date actions

5. ResponseSynthesizer - Response generation with varying context

## Integration Testing

Use existing CLI test pattern:

```php
$results = $knowledgeBase->searchDocuments($query, 3);
```

# Out of Scope

1. Multi-turn conversations (no conversation history)

2. Compliance/security auditing

3. Other platforms beyond UIS

4. Complex actions beyond predefined ones

5. Full-text email generation (template retrieval only)

6. Authentication/authorization (all users same access)

7. On-premise deployment (cloud-hosted only)

# Further Notes

## MVP-Focused Approach

This initial build focuses on the most painful operational workload:

- Helping staff instantly find UIS manual steps

- Deciphering system error codes

- Retrieving email templates

- Finding software installers

- Getting shipping dates for buyout software
